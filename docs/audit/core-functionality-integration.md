## Confirmed overwrite acceptance: 18 November 2026

The browser composition checkpoint is committed locally as `e6d42ee`. Optional overwrite is now integrated through strict contracts, main-owned native selection, preload, utility composition, engine plans, the Windows helper and captured-version/checkpoint previews. The engine bounds reviews and concurrent work, expires authority on wall or monotonic time, clones its internal plan, consumes it before confirmation work and rereads the encrypted retained source. The native helper reacquires canonical fixed-NTFS ancestor/parent proof and the current single-link regular target. Identity, hash, size and write time must match review. Exclusive sharing plus a required exclusive read/write oplock reject open writers, writable mappings and unsupported admission; no weaker fallback is used. A separate CREATE_NEW preservation file is fully flushed and hash/length/identity verified while held exclusively before target mutation. The same target handle writes, flushes and verifies the complete recovered bytes. Failed prerequisites leave the current target untouched.

Write failure attempts verified rollback through that handle while retaining the completed preservation file. Injected failure tests exercise both rollback success and rollback failure. An interrupted write, helper/process crash or power loss may leave an incomplete target; the app does not claim atomic replacement. The reviewed preservation filename remains visible on failure. Overlapped cancellation retains buffers and event ownership until actual completion or one-shot process exit; unobserved cancellation cannot report success. Shutdown cancels helpers, observes exit and drains pending work before store close.

Preservation is an explicitly disclosed ordinary file in the chosen target folder, outside encrypted history, quota, retention and history deletion. No plaintext backup is placed in Rewind's private store. The user keeps/manages this file with normal file tools. It preserves default-stream bytes, not application state, alternate streams or ACLs, and neither output is opened/executed. Recovery is not an AI execution capability.
