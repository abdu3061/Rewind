## Reproduced defects and fixes

### Baseline storage (F07/F08)

1. Repeated adapter open replaced the in-memory database and lost synthetic session state. Fix: preserve the existing successful adapter.
2. Empty/no-schema open returned success. Fix: verify required prototype tables before exposing repositories. Existing initialized database use remains allowed without a migration path; an empty default database now fails deliberately.
3. Missing migration file left the handle open and returned its full path in the error. Fix: clear repositories, rollback/close, retain a handle only if close itself cannot complete, and return a content-free public initialization error.
4. A migration with a valid CREATE TABLE followed by invalid SQL left partial schema on disk. Fix: own an atomic migration transaction and roll back before closing. The test used only a generated temp directory and synthetic SQL; cleanup verifies the resolved fixture path is within the intended temp prefix before recursive removal.
5. Activity/checkpoint BEGIN failure rolled back a caller-owned transaction. Fix: track whether the method successfully began its own transaction.
6. Activity append against a closed database rejected when cleanup rollback threw. Fix: preserve the original structured Result failure if rollback cannot run.

Seven regressions were first red, then green without weakening assertions. Existing repository fixtures now close their in-memory handles after each test. No persistence service, migration framework, public contract, encrypted binding, recovery feature or desktop DB integration was added.

### Baseline renderer (F19)

An extra sandboxed packaged window intentionally loaded the same app page without preload. Initial subscription dereference threw before the Promise error handler; no disconnected alert appeared. A six-line capability guard now renders the existing connection error, keeps Start disabled and permits a safe retry failure. The third app test verifies this. Main still rejects unauthorized-window IPC; the test does not broaden production authorization.

### Separate collector lineage (F01/F06/F15/F27)

Local `audit/collector-stabilization` contains the safe-default, typed PowerShell process-ID and persistent-open failure corrections. Existing `:memory:` missing-runtime prototype fallback remains; it is not approved release behavior. Main's separate fallback, real encryption, async lifecycle and other PR blockers are documented, not silently considered fixed. The subsequent native-test correction prevents ordinary unit tests from reading foreground state. A portable [patch](patches/collector-stabilization.patch) preserves these changes for owner review; it was not applied to shared main or #6.

## Failures and limitations of the audit workflow

- A newly written fixture cleanup threw directly in finally; ESLint correctly rejected `no-unsafe-finally`. Cleanup validation was moved to a bounded helper and the full check passed. This was an audit-test issue, not an inherited product failure.
- One attempted `npm run test:app -- --grep ...` invocation was parsed unexpectedly by npm/PowerShell and found no tests. The direct installed Playwright CLI executed the intended pre-fix failing regression; ordinary unfiltered `npm run test:app` works and passed all three later.
- One versioned Node documentation URL was inaccessible through the web tool; the exact Node 22.16.0 release documentation was then read successfully. A Windows glob search syntax was corrected; this did not change source or invalidate test results.
- Node reports SQLite experimental status; Forge reports upstream experimental-glob output; Playwright warns about color environment variables. These warnings were non-failing and are not native integration evidence.
- No CPU/RAM/latency/long-session benchmark ran. Polling/write/watcher concerns are classified as mechanisms or measurement needs in the architecture plan, not asserted as measured regressions.
