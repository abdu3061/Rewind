# Secure storage and recording integration

Implementation branch: `feature/secure-storage-collection`, based on the completed backend stabilization lineage. Date: 17 November 2026. Nothing is pushed, merged, published, deployed or registered. Existing team branches, worktrees and Git configuration are preserved.

## Milestone status

1. Encrypted storage foundation: implemented in `df4f24e`. Native encrypted SQLite, strict checksummed migrations, integrity validation, encrypted WAL/FTS, Windows-protected key port and fail-closed reopen tests are present. See ADR 0010.
2. Utility process and consent: implemented in `9756cae`, with overload hardening in `ea4ad87`. Main supervises a bounded, validated worker protocol; SQL and collection run in the worker. Launch-scoped consent, persisted exclusions, revoke/drain, restart recovery and synthetic packaged fixtures are connected. Stop requests interrupt adapters even behind queued reads. A saturated main request map terminates the worker instead of dropping revocation; it reports failure and requires reconnect. See [ADR 0011](../decisions/0011-recording-worker-consent.md).
3. Windows recording UI and timeline: implemented in `9d3794b`. Launch-scoped approval, persisted exclusions, truthful collection/error status, encrypted history, session/date/type/keyword filters, composite paging and live committed-write notifications are connected. A lazy PowerShell helper compiles once per recording run, checks exclusions before reading titles, and closes on pause/end. Tests replace every native window API with synthetic observations. `e95874c` adds a preserving migration that indexes observed values rather than JSON property names, plus reproducible clean installs.
4. Conditional browser follow-up: partial, in `8da0352`. Strict candidate message schemas, exact-origin checks, credential/query/fragment URL policy and bounded Windows native framing have synthetic tests. The extension remains inactive. No authenticated pipe, host executable, installer/registry entry, browser permission or Chrome/Edge collection is claimed. See [browser integration](../browser-integration.md).

## Encryption, packaging and process evidence

- Node 22.16.0 / npm 11.7.0 host; Electron 44.11.3 / embedded Node 24.22.2 exact-runtime utility probe. The selected native package is pinned at 13.1.1; see [ADR 0010](../decisions/0010-encrypted-recording-store.md) for primary compatibility sources, cipher parameters and threat model.
- Production opens a real keyed SQLCipher-profile SQLite3 Multiple Ciphers 2.7.0 store. Wrong/missing keys, plaintext, tampering, corrupt settings, changed/future migrations, FK/index integrity failures and unavailable storage fail closed. No memory/plaintext fallback or automatic replacement key is used.
- Synthetic marker scans cover database/WAL and the encrypted search data path. SQLite temporary storage is forced to memory. Key files contain Windows-protected bytes; packaged restart exercises real safeStorage/DPAPI. Unit key-store fakes are explicitly test protectors, not substitutes in production.
- The packaged native binary is unpacked from ASAR and byte-identical to the installed prebuild: SHA-256 `a086560c0d966cf0810005da6db5bd53e624620737a2c09172bf942e67b83f30`. ASAR inspection confirms the utility entry and native license are present. Native compilation is not required for the reviewed Windows x64 install.
- Main retains exact sender/main-frame/location checks. Public APIs have no generic IPC, filesystem, SQL, process-control or key methods. Tests reject untrusted-window session, consent, timeline and reconnect calls; malformed private commands, oversized messages, stale replies and expired process generations are covered.

## Failures found and corrected

1. Existing databases must be keyed before any prepared capability/configuration query. Reopen tests found the initial order error; startup now authenticates first.
2. npm clean-install metadata omitted the upstream `gypfile: false`, causing an unintended node-gyp build. The pinned lock preserves that field; plain `npm ci` now succeeds. `lock:prepare` restores the narrow metadata after dependency changes and `check:install` catches regressions. No global npm configuration or upstream binary is modified.
3. Initial packaged assertions looked in the profile root rather than its `secure` subdirectory. Fixture paths were corrected without weakening encrypted-byte/key-failure assertions. An ASAR inventory assertion also needed Windows separator normalization.
4. Search originally indexed JSON keys. Migration 003 preserves existing observations and indexes only observed values; update/delete/upgrade and external-content consistency tests pass.
5. Revocation now ignores invalid unsaved exclusion drafts. Saturated request/lifecycle queues cannot keep source timers running behind a stop request. Failed helper close still produces failure, even if later cleanup can recover.
6. A disconnected parent port must stop publication before shutdown emits more state. A terminal send guard prevents recursive cleanup, with a regression that makes the port throw and verifies exactly one shutdown and exit attempt.
7. Formatting, strict TypeScript/ESLint diagnostics and focused test failures discovered during implementation were corrected. No production test was disabled or converted into simulated success. Final screenshot review keeps navigation and collection status visible while long history scrolls.

## Remaining release boundaries

No file snapshots/recovery, Gemini, floating notch, browser registration, installer or release is part of this implementation. Browser/folder collectors are not registered. Key rotation/re-encryption migration, retention/deletion orchestration, complete disk quota handling, signing, license reconciliation and independent security review remain release gates. DPAPI does not protect against malware running as the same Windows user. Native probes and automated tests use synthetic data and do not establish real-world foreground accuracy.

Known browser applications are denied by name; arbitrary unknown applications and embedded web content cannot be classified as private browser contexts by this adapter. Do not use this development build for sensitive work. Idle/lock intervals, title-to-file identity and foreground dwell-duration reconstruction are not implemented. Exclusion changes stop future capture and invalidate queued authority; they do not erase previously recorded history. The database page cap does not bound all WAL/physical disk usage. Same-user malware, RAM, OS swap/crash dumps and independent backups are outside the encrypted-file claim.

Full `npm audit` reports 11 moderate, zero high and zero critical findings in the ESLint/typescript-eslint and Forge/ASAR glob/minimatch tooling chains. `npm audit --omit=dev` reports zero known npm findings. No forced audit fix, unrelated major upgrade or unverified override was applied; dependency/native-code review remains a release gate.
