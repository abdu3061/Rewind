# Shared contracts and handoffs

`packages/contracts/src` is the canonical public contract. Zod schemas infer the corresponding TypeScript types. Strict objects reject unexpected properties at implemented IPC boundaries. Other schemas define future boundaries; a schema alone does not authorize a file, user action, or collector.

| Area           | Convention                                                                                                                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity       | UUID strings, generated by the engine/composition owner. No database row IDs in public models.                                                                                                                                           |
| Time           | Canonical ISO 8601 UTC with millisecond precision, e.g. `2026-10-17T09:00:00.000Z`. UI formats in the user's locale/timezone. Event occurrence time is distinct from future internal ingestion time.                                     |
| Results        | `{ ok: true, value }` or `{ ok: false, error: { code, message } }`. No stacks, sensitive raw validation input, paths, or provider errors in public errors. Ports may use `Result<void>` internally; IPC uses cloneable concrete values.  |
| Sessions       | `null` before the first start; `active`, `paused`, `ended` thereafter. Ended state remains inspectable until a new start. Only ended sessions have `endedAt`.                                                                            |
| Activity       | Discriminated `type`/`payload`, event ID, session ID, occurrence time, and source. Foreground, browser visit, file change/opened, idle, lock, capture gap.                                                                               |
| Browser visits | Chrome/Edge, bounded HTTP(S) URL/title, UTC interval, optional bounded article text after permission. No embedded URL credentials. Session linkage must be checked at ingestion.                                                         |
| Files          | File reference identity is `verified-path` or `unverified`. A file version links a file and session to captured time, SHA-256, size, and media type. Physical blob location/key material is private storage metadata.                    |
| Checkpoints    | Named manifest links immutable file-version IDs and browser-visit IDs plus engine-owned project folder references. Kept checkpoints pin the transitive artifact set.                                                                     |
| Search         | Bounded keyword/natural-language query with optional session/time filters. Each result has a typed evidence source reference, time, excerpt, and evidence label; a title-only result never becomes verified identity.                    |
| Recovery       | Engine-owned, expiring proposal ID; save-copy/overwrite mode; explicit confirmation required. Overwrite proposals/results require preservation metadata. No public execute method exists yet.                                            |
| Settings       | Fresh default: collection/cloud/article extraction off, 72 hours, proposed 2 GiB quota, no protected folders, empty exclusions. Collection consent and application exclusions are persisted/editable; other settings remain unavailable. |

The engine must check relationships beyond individual schemas: event/visit session IDs agree, referenced versions exist and belong to the correct file, sources remain accessible after retention, and proposals are current, authorized, and single-use. Absolute paths need OS canonicalization and root/reparse/race checks; a string field or `verified-path` label is not sufficient.

## Public desktop API today

`window.rewind.sessions` exposes get/start/pause/resume/end/onChanged. `runtime` exposes get/retry/onChanged; snapshots separate service, collection, session, verified storage and launch-scoped consent. `privacy` gets/updates collection permission and up to 200 application exclusions. `timeline.query` accepts a validated session/date/type/literal-keyword filter and composite cursor, returning up to 100 events; `timeline.onChanged` carries only the committed session ID. `history.list` pages sessions by startedAt plus ID. Methods return structured Results; subscriptions return unsubscribe functions. No private worker initialization/shutdown, raw IPC, database, filesystem, AI or key capability is public.

`rewind:session` and `rewind:recording` accept exactly one strict command DTO from the known main frame/location. Main validates private worker version/boot/request IDs and leaf responses; preload validates public replies/events again. The worker envelope cap is 2 MiB, sufficient for 100 maximum escaped title DTOs; ingestion remains capped at 128 events/256 KiB per batch. Commands and read models serialize around lifecycle commits. Renderer generation/revision guards discard stale responses. See ADR 0011 for startup, crash, restart and lease behavior.

## Interfaces for parallel work

`ports.ts` defines session/activity/file/checkpoint/search repositories and the Collector lifecycle (`start`, `pause`, `resume`, `stop`). Collector context supplies session, privacy settings, an ingestion callback, and a short-lived generation ID. Future engine ingestion must reject stopped/paused/stale generations independently of collector self-report.

Storage retains the stock-SQLite synthetic prototype and adds production SecureStorage and the protected-key port. Only the encrypted adapter is composed in the worker. Collectors export Windows foreground collection and lifecycle types; native browser framing is tested but inactive. Browser/folder event ingestion is unavailable without an engine resource-authorization port. Assistant remains an interface. Test fakes must never become silent production fallbacks.

`SessionStorage` supplies open/close and the session/activity repository subset; opening failure exposes no successful runtime and never selects another adapter. Collector start/resume establish readiness, and emits before engine commit can fail. Stop is idempotent and must await owned query/emit/resource work; resume accepts a fresh context after stop. The engine additionally rejects stale closures/session/source/policy and drains admitted operations. See [ADR 0009](decisions/0009-session-lifecycle-stabilization.md).

`ActivityRepository.append` validates active session linkage and atomically writes file-opened references with activity rows. File changes require an existing identity; neither reference existence nor stored verified-path text authorizes filesystem access. Browser interval/session linkage is validated by the activity schema. Activity `list` accepts `{ occurredAt, id }` for complete descending pagination. The old timestamp argument remains an exclusive time filter and cannot enumerate ties; pending PR consumers must migrate explicitly. The prototype search supports literal bounded keyword queries and actual scoped version IDs; natural-language search is unavailable. Production timeline queries use an encrypted external-content FTS index with parameterized literal terms, date/session/type filters and composite cursors. Expiration remains future work.

Lead-approved contract PRs land before implementation PRs that require changes. Prefer additive narrow fields; update runtime schemas, type consumers, tests, and this document together. Database migrations and utility/native wire protocols have independent versioning; do not expose raw database fields to make a frontend task easier.
