# ADR 0034: Encrypted captured-content indexing foundation

Status: implemented locally for Rasit's review. The storage and engine foundation is exercised with synthetic fixtures. Automatic worker composition, public capabilities, Search controls and packaged acceptance of content search remain required. This does not enable indexing in ordinary sessions or approve a remote merge/release.

## Context and choice

The specification's Versions requirement preserves original bytes and extracts searchable text separately. ADRs 0031–0033 provide bounded previews, but ordinary local search still covers recorded observation metadata and filenames. Indexing only after the user previews a file would leave most captured bodies unsearchable. The chosen direction is automatic indexing of newly captured eligible versions under the current active-session/file grant, plus a distinct explicit saved-history backfill/retry action. Saved-history indexing reads retained encrypted bytes; it must never become live filesystem collection or cloud approval.

Migration 010 adds a derived `file_text` row per actual retained captured version, with its original content hash, extractor revision, format, bounded text/hash or explicit unavailable reason, truncation/page metadata and indexing time. The existing native cipher, protected key, startup integrity checks and encrypted journals cover these rows and their external-content FTS5 index. There is no second database or plaintext text cache. Existing migration SQL/checksums are unchanged. A version-nine history upgrades in place, preserving sessions, settings and sealed credential records.

Source guards reject orphan/mismatched writes and modification of successful extraction. Unavailable attempts may be explicitly retried; cancellation is never stored as a durable failure. Foreign-key deletion removes text with its original version and triggers remove associated FTS tokens in the same transaction. Existing transitive checkpoint Keep determines whether the original survives ordinary deletion, expiration and quota eviction; its derived text follows that lifetime. Including kept evidence in confirmed deletion removes both. These choices follow SQLite's [external-content FTS guidance](https://sqlite.org/fts5.html#external_content_tables) and [foreign-key cascade semantics](https://sqlite.org/foreignkeys.html#fk_actions). Application checks and native tests verify the behavior with foreign keys enabled; neither mechanism alone establishes encryption or forensic erasure.

## Admission and bounded work

`FileTextRepository` is obtained only from an opened, verified `SecureStorage`. A write rechecks actual retained original bytes, SHA-256 and media type inside its owned transaction and checks the current authorization callback before commit. It refuses a caller-owned transaction. Successful extraction is immutable for revision one. Physical database/journal usage plus a conservative write reserve gates publication; quota refusal preserves the original. An ambiguous SQL/rollback failure is an unavailable result for the runtime owner to fault and drain, never a fabricated successful index write.

`FileTextIndexer` orchestrates ports without importing storage, Electron, collectors or the parser package. It takes one candidate at a time, with a fixed through-time and exclusive `(capturedAt,id)` cursor. Automatic scope requires an explicit session, selected folder IDs and no retry of prior failures. It verifies returned scope, metadata, full original hash and bounded byte length before extraction. Current engine policy is checked around every asynchronous boundary and again through the publication callback. A skipped/deleted source yields to the event loop; no large candidate/BLOB queue or synchronous backlog loop is created.

UTF-8 extraction uses at most 64 KiB, ending on a complete code point. Invalid UTF-8 becomes an unavailable extraction without fabricated replacement text. PDF/DOCX use the existing `DocumentProcessor` port and its separately supervised utility limits (16 MiB original, 64 KiB text, 50 PDF pages). The new indexer does not directly invoke those parsers in production. The synthetic storage integration test invokes the real parser implementation in the test process, which is distinct from packaged utility acceptance.

An active preview has priority. A busy processor interrupts the index pass without persisting a false document failure; a cancelled parse also remains pending. An unavailable parser or real malformed/encrypted/over-limit document has an explicit result. Extraction output is validated before storage. One owned byte buffer is cleared on completion/failure; no JavaScript string/heap-erasure guarantee follows.

## Shutdown and shared ownership

The private `DocumentProcessor.stop(owner?)` accepts an optional owning AbortSignal. A stale owner cannot terminate a replacement request. An unconfirmed owner survives timeout/failed result and remains stoppable; stop/closure receipts remain correlated and newer actual closure cannot be replaced by an older failed stop.

The indexer invalidates authority synchronously. Its `stop()` confirms only that owner's parser closure and deliberately does not await a read/publication queued on the coordinator from inside that coordinator's own callback. `settled()` is awaited outside the queue before storage closure. A returned result does not clear an unconfirmed process: the indexer stays busy, blocks replacement and retains its owner for a stop retry. Stop exceptions are also unconfirmed. `close()` denies new work, confirms stop and observes settlement. All of these contracts must be preserved by worker composition.

## Retrieval and remaining integration

Private search uses parameterized, quoted literal AND terms (at most 30), session/date filters and stable timestamp/UUID paging. At most 25 hits expose actual captured-version summaries and UTF-8 snippets of at most 1,000 bytes. Random internal match markers locate the snippet window, are removed before return and are never HTML. Every returned hit rechecks the stored text hash and actual original bytes/hash one at a time. Startup also verifies the derived schema/triggers, cipher/FK integrity and external-content FTS consistency. Unsupported originals remain recoverable independently of search.

Normal frontend controls and the recording runtime do **not** yet invoke this foundation. Next compose automatic and explicit backfill admission, preview priority, progress/Stop, current retention and policy checks, root fault handling, typed public search/status commands and escaped Search results with source-generation receipts. Track the displayed/pending result sources for pre-commit invalidation on deletion/expiration. Show pending/unavailable/truncated limits and retry honestly. Verify these through real packaged main/preload/worker/parser/store paths before claiming ordinary content search works. No renderer/provider capability may accept body writes, source hashes, parser commands or filesystem paths.

Gemini's sharing review remains metadata-only. Adding local document hits must not make their bodies/snippets automatically shareable or authorize destructive recovery. Rich layout, OCR, article extraction, idle/lock and distribution/security gates retain their separate scope.

## Verification

The focused storage, indexer and private parser-owner suites pass 73 tests across four files. Eighteen native-cipher storage tests cover actual UTF-8/DOCX/PDF engine indexing, encrypted restart/marker scans, source/text tampering, FTS corruption, migration-nine upgrade, literal/snippet/paging bounds, authorization rollback, failed writes, retry, quota eviction, expiry/deletion and transitive Keep. Twenty-seven indexer tests cover queued read/commit revocation, scoped candidates, bounded Unicode text, immutable admission, malformed parser replies, preview priority, honest pending work, failed closure/retry and shutdown. Four additional owner tests extend the existing client/process suites. The implementation report records complete repository/build/packaged results separately; these focused tests do not prove the missing UI/runtime composition.
