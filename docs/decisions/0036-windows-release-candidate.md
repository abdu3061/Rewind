# ADR 0036: Windows release candidate and passive installation

19 November 2026. Owner: Rasit; implemented locally under the release-hardening goal for review. This approves no publication, remote merge, license selection or independent security claim.

## Context and decision

The completed core on `feature/core-functionality` is newer than the divergent prototype merged into remote main. Preserve `395fa03` and its ancestry. The local candidate starts from that core. A merge simulation reports 30 conflicted paths. The old stock-SQLite/fallback/main-collector/assistant routes are superseded by the current encrypted utility composition and reviewed-evidence API. Keep PR #3 separate: its renderer bootstrap introduces a mock bridge. See the release-readiness integration disposition before reconciling ancestry; never resolve these conflicts by choosing remote files wholesale.

Add the Forge 8.0.1 Squirrel maker alongside ZIP, with a fixed `Rewind` application identity and original beta icon. Squirrel is a per-user installer candidate, not a signed/accepted release or an automatic update service. Keep source/workspace versions at 0.1.0 until the owner selects release versioning and publisher identity. No new application/runtime framework is introduced. Alternatives were retaining ZIP-only distribution (fails installability objective) or MSIX/MSI (requires a separate identity/tooling/support decision). The maker, Forge fuses plugin 8.0.1 and Electron fuses 2.1.3 are build dependencies only.

An early bootstrap handles only exact packaged Windows Squirrel install/update/uninstall/obsolete events, before importing desktop/service composition. Install/update creates fixed Start Menu/Desktop shortcuts via the sibling Update.exe; uninstall removes them. Obsolete exits. First-run is an ordinary default-off launch. Unknown/foreign-layout events fail safely. Shortcut subprocess arguments are fixed, shell execution is disabled, output is discarded and execution has a deadline. No installer invocation loads DPAPI keys, starts collectors, deletes data or changes browser registrations. Preserve encrypted history, credentials, settings, and browser ownership receipts across uninstall. The documented explicit in-app cleanup precedes uninstall; unattended browser-registration cleanup is deliberately not fabricated without its ownership journal/verification. Unknown registry entries remain untouched.

## Binary hardening and signing

Forge disables RunAsNode, NODE_OPTIONS/NODE_EXTRA_CA_CERTS and file-protocol extra privileges; enables cookie encryption, embedded ASAR integrity validation and ASAR-only startup. Normal `build` retains the main-process inspector needed by Playwright; those folders are verification builds. Root `make` rebuilds with the inspector disabled **before signing**. The maker rejects invocation without this explicit artifact mode. Never distribute a normal `build` folder as the final candidate. `verify:release` requires all release fuse values, compares the tested executable/ASAR/inventories against ZIP and NuGet payloads, and launches the hardened executable with ignored Node/debugger injection attempts in a marked temporary synthetic profile. ASAR integrity is code integrity, not history encryption. Unpacked addons/resources remain a separate supply-chain/signing review boundary.

An optional owner-controlled external CommonJS signing function is loaded only by build tooling. Forge and Squirrel use the same adapter; `REWIND_REQUIRE_SIGNING=1` fails without a configured module. Signer failures produce a fixed code. Authenticode changes native-host bytes, so the adapter refreshes the adjacent browser inventory immediately after signing that host, preserving the native source fingerprint and exact runtime hash checks. Unit tests use fake signature bytes only. Actual certificate, token/HSM, timestamping, trust-chain verification, Squirrel signing callbacks and signed installed-host acceptance remain manual release gates. Do not log secrets in an external signer.

## Diagnostics and UI

Code-only operations logs rotate at 64 KiB with one prior file. Records contain UTC time and a fixed operational code, never errors, titles, paths, URLs, document bodies, questions or keys. Logging failure cannot alter service authorization. No crash-upload or telemetry service is added. Single-instance locking precedes service creation; a second launch focuses the existing window. Renderer loss requests the same acknowledged shutdown as Quit, preventing invisible continued recording. Startup failures show a fixed support code and do not reset history.

Release review also found a P1 shutdown composition defect: failed or pending native credential-prompt closure could gate the worker's shutdown request. Start prompt closure and worker revocation/drain independently, track both settlements, and acknowledge Quit only when both succeed. A thrown/stuck prompt cannot delay initiating source revocation, and a failed acknowledgement still prevents a successful quit claim. Tests exercise pending prompt, thrown close, worker failure and retry without changing any process deadline.

Keep the existing UI. Add a keyboard skip link, textarea/link focus indication, compact minimum-height navigation and an honest secure-history connecting state. Screenshots and keyboard/overflow checks cover the actual six packaged screens at 800×600. This is not a screen-reader/high-DPI/accessibility certification.

## Notices, acceptance and limits

Build-time notice generation inventories exact runtime roots and required installed dependency closures, copies upstream license/NOTICE material and hashes each file. It is intentionally overinclusive and is not a complete embedded-native legal review. Electron/Chromium notices remain beside the executable; missing notices and embedded SQLite/crypto/Skia/font terms require owner reconciliation. Rewind remains private/UNLICENSED.

The release-readiness report records exact check/build/test results and unresolved manual gates. New tests cover installer events/failures, bounded diagnostics, signed-byte inventory changes, minimum-window keyboard navigation, renderer-crash drain/restart and passive installer-obsolete startup. No real personal activity or document, production registration, live key/account request, publisher certificate, real-user installation or remote write is used.
