# ADR 0013: scoped Windows file capture and independent approval

17 November 2026. Implemented locally under the core integration goal; Rasit retains final review and merge/release authority. This does not authorize publishing or distribution.

The utility process registers a protected-folder collector alongside the Windows collector. `folderCollectionConsent` is independent of Windows foreground approval, expires on every worker launch and requires an active session. Changing protection settings invalidates the run, stops/drains sources and pauses without automatic resume. A worker snapshot explicitly distinguishes file approval, so main cannot mistake file-only recording for unauthorized Windows polling. All existing sender/main-frame/location and sandbox checks remain.

Main opens the native folder dialog. Public IPC cannot nominate a filesystem path. Worker-only selection checks reject private Rewind storage and its ancestors, application profiles and system directories. Synthetic mode additionally confines selection to the isolated fixture profile. Selection stores a canonical path and real Windows directory identity, but it does not approve content collection.

Capture uses bounded periodic reconciliation through the Windows handle adapter. This replaces the proposed notification-first watcher for this implementation: Node path-based watchers would add namespace race and overflow behavior without authorizing reads. Native enumeration holds ancestor directories, rejects reparse points and case-sensitive directories, and validates the selected directory's current identity on every operation. It checks fixed NTFS volumes, real final handle paths, single-link files and before/after file metadata. Read sharing denies concurrent writers and deletion. Failed/unverifiable reads never produce a version. Polling cannot guarantee every brief intermediate save; the UI says so. Rename/move attention and unsaved application state are not inferred.

Each folder selection has an ID. File bindings persist IDs by selected folder and relative path; new identities get random IDs only when a complete capture commits. Subsequent saves, atomic replacements, resume and restart resolve the existing binding. Exact filename spelling is preserved in in-memory queues: JavaScript lowercasing would conflate some distinct Unicode filenames. SQLite's existing ASCII case-insensitive binding supports ordinary case-only spelling changes; broader rename/move correlation is not promised. Each immutable version also stores the actual source OS file identity.

The collector stages one bounded original-byte read. Engine source/session/generation/exclusion checks then authorize an individual atomic capture. The storage transaction publishes verified bytes, file identity, version and observation together, rechecking authority before commit. Failed publication makes the source stop reading immediately, even behind lifecycle backlog. A source can report unavailability through its current generation only; a stale callback cannot stop a new run. Stop interrupts the helper, drains reads/emits, wipes mutable byte buffers and retains a failed-close handle for retry. The helper is passive between explicit requests; it never starts monitoring itself.

The supported envelope is 16 MiB per file, 240-character local paths, 2,000 enumeration entries across selected roots and 16 levels. Hidden/build trees are skipped. Text/code, Markdown, DOCX and PDF original bytes are preserved; safe UTF-8 text previews are bounded and escaped. Document rendering/extraction remains a separate bounded-worker task. Filename FTS indexes observed names, never JSON keys or an inferred title-to-path match. An initial capture is labelled `captured`, not a fabricated filesystem creation event.

Identical bytes share an immutable encrypted BLOB. Recent consecutive identical versions are deduplicated. Active protection periodically re-verifies unchanged bytes before normal retention expires; a sufficiently old observation creates fresh metadata referring to the same BLOB. This avoids losing the only current capture during a long unchanged session without retaining expired activity forever. Kept checkpoints retain their actual selected versions.

Version list/info/preview reads enforce cleanup. Visible previews periodically recheck retained metadata and disappear if it expires, is deleted or becomes unavailable. A failed integrity check revokes capture rather than serving unverified bytes. Storage admission reserves conservative headroom and reports `STORAGE_LIMIT` distinctly; quotas are application backpressure, not a filesystem hard reservation.

Evidence: engine pending-preparation/pause/publication-failure tests, actual Windows synthetic-file worker integration, native lock/link/junction/replaced-directory/max-size/cancellation tests, Unicode identity/retention freshness tests, and the packaged Files flow. See the [integration report](../audit/core-functionality-integration.md) for exact final command results. No test touches personal documents or real browser history. [Windows file information classes](https://learn.microsoft.com/en-us/windows/win32/api/minwinbase/ne-minwinbase-file_info_by_handle_class) define the directory case-sensitivity query.
