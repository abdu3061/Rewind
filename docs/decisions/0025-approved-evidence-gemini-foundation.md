# ADR 0025: bounded Gemini access to explicitly approved evidence

18 November 2026. Private service foundation implemented locally, pending Rasit's review. Desktop credential handling, engine-backed review issuance/revalidation, public consent and Search UI composition remain unfinished. **Normal app cloud requests remain unavailable.** This decision does not claim live provider verification, completed Gemini integration or release approval.

## Decision

Use only the official `@google/genai` SDK, pinned at 3.5.0 with its actual published types. Its Node 22 minimum fits the repository's supported runtime. Do not add ADK, a dependency framework, remote persistence, server auth or cloud file storage. The selected development model is `gemini-3.8-flash`, listed as stable with function calling/structured output support in Google's current model documentation. Model/provider changes need review and fresh compatibility checks; no model or endpoint is supplied by a renderer or observation.

The assistant receives an engine-issued immutable approved plan, not arbitrary model-selected local access. A plan contains a question and at most twelve bounded evidence records with typed actual source references. Each has an opaque E1-E12 key, timestamp, title, excerpt and evidence classification. The private request is capped at 24 KiB and requires literal confirmation. This data shape alone is not authorization: composition must issue a single-use plan after user review, compare its immutable approval epoch and verify current source existence, retention and exclusions. Verification receives copies and cannot mutate the reviewed evidence pool. The package does not implement or bypass these future desktop/engine gates.

The first SDK call sends the approved question and a minimal key/time/title manifest. The only declared tool, `get_approved_evidence`, can select one to four keys from that already approved pool. No filesystem, network, shell, settings, recovery-confirmation, overwrite or deletion tool exists. Unknown tools, extra arguments, duplicate/unknown keys, more than four calls or more than twelve selected records fail. The second independent SDK call receives only the approved excerpts selected by those validated calls, without private source UUIDs. It produces structured answer text, citation keys and an explicit insufficient-evidence flag. No additional model loop or chat backlog is used.

Returned citation keys must resolve to evidence actually fetched from the approved pool; the service maps them to the original typed source references. Answers marked sufficient require real citations. Empty evidence returns a deterministic local missing-evidence result without any provider call. Current authorization and source verification are checked before planning, between requests and before publication. Captured text is untrusted data, never executable instructions or tool authority. These checks validate provenance and capabilities, not the factual truth of arbitrary generated prose; future UI must identify generated text and let users inspect evidence.

## Budgets and cancellation

The fixed transport accepts only HTTPS POSTs to Google's exact generateContent endpoint for the selected model. Redirects, custom endpoints and URL query data are refused. Request bodies are capped at 32 KiB each and 48 KiB cumulatively. Provider responses are streamed under a 128 KiB cap before SDK JSON parsing. There are at most two network calls, one candidate and 512 planning / 2048 answer output tokens. Automatic SDK retries, function execution and continuation are disabled explicitly. The model uses supported low thinking rather than an unsupported minimal setting.

An overall 30-second deadline and 12-second SDK request timeouts use cancellation signals combined at the actual transport boundary. Current approval is checked again immediately before fetch. Revocation/cancellation invalidates the service epoch, aborts active requests and rejects late responses. It cannot retract a request already accepted by Google or eliminate provider charges/retention. One request runs at a time; an aborted underlying request remains tracked and blocks reuse until it settles. Shutdown observes completion or returns a retryable failure. Timers/listeners are cleared. Review IDs are consumed before work and bounded per launch; retries require a new review.

API keys remain utility-only and are never accepted through these evidence/tool schemas, logged, returned to the renderer or placed in `VITE_*`. Raw provider/verifier errors are replaced with bounded generic errors. Reviewed text containing the configured credential is refused before transmission. A trusted synthetic fetch seam is used only by tests; no production URL/configuration capability is exposed. ESLint rejects assistant/SDK imports in renderer, preload and extension sources. Proper OS-protected credential entry/storage and engine-issued review capabilities must be implemented before normal composition.

## Evidence and remaining work

Fifteen focused tests run the actual official SDK against synthetic HTTP responses. They verify exact endpoint/key-header usage, minimal first payload, approved excerpts and private-ID omission, two-call configuration, single use, default denial, no-evidence behavior, mid-request revocation, deletion/exclusion verification, immutable evidence, final source refusal, invented citations, invalid tools/arguments, function floods, truncated/oversized output, untrusted captured instructions, sanitized provider failures, disabled retries/continuations, deadlines, retained work and retryable shutdown. A global network guard rejects accidental real fetches. No live key or provider request is used.

Next implement private native credential entry and encrypted credential storage, actual engine-backed search/review/source revalidation, explicit cloud opt-in and per-question approval, narrow public controls and Search presentation. Then verify that entire path with synthetic profiles/provider responses and clearly report the absence of live-key evaluation. Core recording/recovery must remain usable with cloud off or unavailable.
