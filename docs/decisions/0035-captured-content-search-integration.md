# ADR 0035: Captured-content indexing and normal Search integration

Status: implemented and verified locally for Rasit's review: 616 tests / 69 files, Windows build, all 22 packaged app tests, all 6 installed-browser tests and the actual-ASAR document harness pass. No remote merge, publication or release is authorized.

## Context and choice

ADR 0034 supplies an encrypted derived-text repository and indexing engine. This decision connects that foundation to the normal recording utility and Search screen, closing the difference between searching a captured filename and searching actual retained file content. Reuse the existing selected-folder consent, coordinator, separately supervised document processor, cipher database, recovery controls and design system. No dependency, new database, cloud service, renderer filesystem API or collection source is introduced.

`ContentOperations` is composed beside `FileOperations` in the recording worker. Confirmed capture commits schedule a kick outside the coordinator callback. A five-second timer retries pending current-session work after a preview interrupted it. Automatic admission requires ready storage, no pending document/privacy mutation, active collection and session, the current file-capture launch grant and selected folder IDs. The engine freezes a through-time and processes one eligible unindexed source at a time. Automatic passes skip previous extraction failures. Start/resume and a file grant can schedule a pass, but never grant monitoring or resume a paused session themselves. File approval during an existing active session follows the existing pause-and-explicit-resume policy.

Search also offers explicit **Index saved content**, with an optional **Retry unavailable documents** checkbox. This reads only retained encrypted versions, including past/paused sessions. It requires an explicit confirmed request and current application/policy authority; it grants no file collection or cloud permission. It can replace automatic work only after owned stop and actual work settlement. **Stop content indexing** synchronously invalidates the pass, confirms owned parser shutdown and pauses automatic indexing for this launch. A later explicit saved-content indexing request resumes automatic indexing when its independent capture conditions are satisfied. Worker/app restart does not resume collection approval.

## Source, policy and lifetime

Candidate metadata, folder binding and version identity are reread through the coordinator before original-byte access and again before publication. Changed identity is an integrity failure. Excluded paths are additional denials, using the shared Windows case-folded path policy; path labels never authorize filesystem access. Actual original bytes/hash and extractor format are checked by the engine and encrypted write transaction. Policy is checked around asynchronous boundaries and at commit. UTF-8 decoding stays bounded; PDF/DOCX parsing remains in the pre-admitted resource-limited utility. Slow parsing releases the coordinator.

Pause/end, privacy/storage/checkpoint mutations, unavailable service and shutdown invalidate index authority. Explicit maintenance confirms owned index stop and the global preview drain before storage mutation. The indexer's queued read/publication settlement is awaited outside the coordinator before storage closes. A synchronous document-mutation counter denies new automatic or manual indexing during pending policy mutations. Critical storage/integrity/unknown-closure errors fault the service and revoke launch approvals; a parser's explicit malformed/encrypted/unsupported/limit result remains a recoverable source with unavailable extracted text. Quota refusal is visible and leaves original bytes intact.

The private processor is shared with preview priority. Automatic work does not start while a preview request is active; a busy processor interrupts a pass without recording a false permanent document failure. Preview preflight can stop background work. Preview cancellation now passes its own AbortSignal, including after an unconfirmed result, so an old screen cannot stop a replacement background job. Explicit maintenance retains global stop authority. No cancellation receipt is treated as successful publication or completed process exit without the existing closure proof.

## Public controls, queries and invalidation

The only added `window.rewind.content` capabilities are `state()`, `indexSaved({confirmed:true,retryFailures})`, `stop()`, `search(query)` and `clearSearch()`. Main validates the recording command and sender/frame/location; worker commands remain boot/request fenced. Main and preload validate dedicated response schemas. Strict argument validation rejects extra paths, keys, body text, source hashes, private run scopes and owner IDs. There is no public extraction/write capability. Stop/clear remain recognized denial operations in the main worker client, and bounded search/admission requests use a deadline suitable for the private parser lifecycle.

The Search form's submitted keyword/session/date filters feed both recorded metadata and captured text. A specific non-file event type suppresses file-text results. Captured-text queries use at most 500 characters, 30 literal terms and 25 results per page. Current folder exclusions are checked before original-source BLOB verification/output. A page scans a bounded source window and returns an optional `(capturedAt,id)` continuation cursor exactly when more raw matches exist. This lets an empty policy-filtered page advance without an unbounded scan or leaking its snippets/paths. A cursor is display/query metadata, never file, process or recovery authority.

Results carry the actual captured-version summary, an escaped UTF-8 snippet of at most 1,000 bytes, extraction format/truncation and current document generation/revision. Text and actual original-byte hashes are verified one source at a time. The worker retains only the latest displayed page's at-most-25 version IDs plus a pending-query flag and the indexer's active version. Storage's synchronous pre-commit existence callback invalidates a displayed/active removed source before expiration/quota deletion commits. Unrelated expiration preserves a retained or kept result. An in-flight query is conservatively invalidated, and stale replies fail instead of publishing. `clearSearch()` releases that screen's source tracking on navigation. Explicit privacy/maintenance invalidates all current document receipts.

The renderer masks mismatched-generation snippets/previews immediately, rejects superseded queries, cancels its owned preview on replacement/navigation and polls bounded progress without overlapping status requests. It shows indexed/pending/unavailable counts, current work/error, launch pause, retry, source identity, truncation and extraction limits. Plain React text/`pre` renders untrusted markup literally. Search opens the existing verified preview and confirmed copy/overwrite recovery controls; recovered files are still exact original bytes. An extraction failure does not prevent finding/recovering originals from Files or checkpoints.

## Privacy and technical limits

Derived text and FTS tokens retain ADR 0034's cipher, quota, source-cascade and transitive Keep lifetime. Automatic indexing uses only actual captured bytes; saved-history indexing never rereads live source paths. Bodies, snippets and full paths are excluded from the existing assistant's metadata evidence picker and tools. Local indexing grants no Gemini key, cloud approval or sharing review. Article extraction, OCR, rich layout and idle/lock remain unavailable. The Node parser utility remains resource-limited rather than an OS filesystem/network sandbox. No forensic erasure, hard filesystem quota, signed distribution or live-provider claim is introduced.

## Verification and test scheduling

Focused checks pass 37 tests across five files: the real worker/cipher/engine path for three formats, default-off approval, explicit resume, encrypted restart, launch-scoped Stop, paused backfill, durable failure/retry, delayed parser result after deletion, current exclusions, source-specific pre-commit invalidation, kept/unrelated cleanup, strict DTOs and encrypted repository behavior. Existing preview tests also verify owned cancellation. The new normal-app test has exercised actual packaged parser utilities, body-only keyword matches, literal markup, verified DOCX copy recovery, kept evidence through deletion/restart and final removal. The second packaged flow exercises stopped automatic work, paused backfill, unavailable encrypted PDFs, explicit retry and invalid preload arguments. The untrusted-window test now denies all five content capabilities as well.

An unrestricted suite run exhausted several existing Windows native deadlines. A one-worker run passed all other suites but repeated 4096-bit RSA generation still timed out unrelated credential lifecycle tests. Test files now run with one worker so native admission/exit deadlines do not compete with unrelated test processes. Credential clock/validation cases use two distinct real synthetic 4096-bit recipients generated once in suite preparation; real OAEP encryption/decryption, distinct-recipient/replay assertions and all existing test deadlines remain. The first acceptance case retains production key generation, and native/packaged credential coverage remains. Production cryptographic parameters and parser limits are unchanged. This changes scheduling and fixture preparation, not failure assertions or product security.
