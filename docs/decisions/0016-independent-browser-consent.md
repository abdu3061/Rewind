# ADR 0016: browser collection has independent launch authority

17 November 2026. Browser implementation in progress under the core goal. Independent consent is implemented locally; native host, authenticated pipe, extension capture and registration are not implemented by this slice. Rasit retains final review and merge authority, with Mohammad Poorhamadi owning browser transport.

Windows foreground approval must not authorize a browser collector. `browserCollectionConsent` now defaults false independently of Windows and selected-folder approvals. The coordinator starts/adopts events only from the specifically approved source. Browser-only approval does not start Windows/folder sources. Global revoke, storage maintenance, failed persistence, faults and shutdown clear browser approval alongside other recording authority. Launch always resets it before any collector initialization, and worker readiness with any recording approval fails closed.

Runtime snapshots explicitly expose `browserPermission`; main validates startup and active-state invariants using the independent flags. Existing settings JSON upgrades with a default-off browser field; there is no new SQL migration or dependency. No public browser grant API or browser collector is installed yet, so ordinary desktop operation still cannot record browser visits. Extension permissions/listeners remain inactive. Synthetic engine tests prove source independence and stale-context rejection without opening a browser; supervisor tests reject forged initial Windows/file/browser grants.

The remaining native boundary must authenticate the actual same-user peer and exact extension caller before granting a bounded session/generation connection lease. Native Messaging caller-origin syntax alone is insufficient. The implementation must also handle expiry/replay, pause/end acknowledgement, disconnects, exclusions, explicit extension permission and isolated Chrome/Edge verification. No default-on monitoring, static public bearer token, local HTTP service or article extraction is authorized by a consent flag.

Primary references checked during implementation: [Chrome Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) documents executable stdio hosts, exact origin allowlists, Windows registration and framing; [Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging) documents Edge registration/lookup and store-specific IDs. [Chrome's extension testing change](https://developer.chrome.com/blog/extension-news-june-2025) means tests must select a supported isolated loading method instead of assuming the ordinary Chrome command-line flag works. Windows Chrome, Edge and the C# compiler are present locally; presence is not evidence of browser end-to-end verification. No production host or registry entry has been installed.
